# 09 UI 重设计方案

本文件是 QuantLab 前端第三轮重设计的依据。上一轮（见 [`08-UI升级调研与实施方案.md`](08-UI升级调研与实施方案.md)）解决的是"首页说什么"，本轮解决的是"整个产品长什么样、信息怎么组织、数据怎么呈现"。

## 一、为什么要重做

对现有线上版本（`https://quantlab.aihzcc.top`）和 `frontend/src/main.js`、`frontend/src/style.css` 做完整审计后，确认了六个结构性问题。它们不是配色偏好问题，而是会直接影响可用性和可信度的问题。

| # | 问题 | 具体表现 | 影响 |
| --- | --- | --- | --- |
| 1 | 形态混淆 | 面向访客的营销首屏被放在带侧边栏的后台外壳里 | 既不像产品官网，也不像研究工具 |
| 2 | 涨跌语义与用户习惯相反 | `up=#22c55e`（绿）、`down=#ef4444`（红） | 中文金融用户默认红涨绿跌，读反会造成实质误判 |
| 3 | 数据大量闲置 | 后端已返回 `trades`、`orders` 与 10 项指标，前端只渲染 6 项指标，交易明细完全没有界面 | 平台自称"证据链"，却看不到证据 |
| 4 | 信息密度过低 | 圆角 16–20px、卡片内边距 22px、首屏几乎无数据 | 与量化用户对专业工具的密度预期不符 |
| 5 | 缺少状态设计 | 加载、空、错误共用顶栏一个文本 pill | Render 免费实例冷启动 30–60 秒期间，界面长时间显示 `--` 且无解释 |
| 6 | 视觉语言错位 | 青绿→天蓝渐变按钮、多层发光、背景网格 | 呈现为通用 AI 产品风格，金融专业感不足 |

## 二、调研结论

调研覆盖国内量化平台（聚宽、BigQuant、米筐、果仁、雪球）与国际量化平台（QuantConnect、Composer、TradingView、Koyfin、Portfolio Visualizer），以及 2025–2026 年金融数据产品的通行设计规范。以下是对本轮设计产生直接约束的结论。

### 2.1 中文金融产品的硬性惯例

- **红涨绿跌不可妥协。** 实测色值：雪球 `#F04848` / `#22A875`，果仁 `#FF4848` / `#41CD4B`。正收益显式带 `+` 号，百分比保留两位小数。
- **品牌色必须避开红绿。** 因为红被"涨"占用，国内平台品牌色几乎一律为蓝：聚宽 `#3C7EEE`、米筐 `#2A76E6`、果仁 `#2C7CDA`。
- **密度即专业。** 正文 14–15px，表格可到 13px。被 Wind、同花顺一类终端训练过的用户，会把"稀疏"读成"业余"。
- **风险提示两处布防。** 页脚常驻一条；回测结果图表旁必须就近提示"历史回测收益不代表未来表现"。
- **策略清单默认表格视图**，卡片是次选。表格里直接给年化、回撤、夏普这类可比较的数字。

### 2.2 国际平台的结构经验

- 米筐首页按投研工作流逐屏推进（数据 → 回测 → 风控 → 归因），访客在滚动中完成一次心智演练。
- 果仁把"量化交易"翻译成 1–5 编号步骤，显著降低入门心理门槛。
- TradingView Strategy Tester 把结果分成"概览 / 绩效摘要 / 交易列表 / 属性"层次：先给关键指标，再允许下钻到每一笔交易。
- 落地页与工作台是两套外壳，不混在一起。

### 2.3 本轮不采纳的做法

- 不虚构用户数、累计回测数、收益率或客户背书。
- 不引入社区、克隆策略、积分商城等运营机制——当前产品没有账号体系，做了就是假的。
- 不添加需要新后端能力的界面。本轮只重做前端。

## 三、设计原则

1. **数据优先于修饰。** 任何一块面积，先问"这里能不能放一个真实数字"。装饰性渐变、光晕、背景网格一律移除。
2. **一次只用一种强调手段。** 颜色、加粗、边框、背景四选一，不叠加。
3. **颜色永远不是唯一编码。** 涨跌除颜色外必须同时有 `+`/`-` 符号或箭头，保证色觉障碍用户可读。
4. **诚实的状态。** 加载就说在加载，冷启动就说明原因和预计时间，失败就给可操作的下一步。
5. **同一数据在任何页面呈现方式一致。** 收益率、金额、日期、代码各有唯一格式化函数。

## 四、设计系统

### 4.1 颜色

深色为默认且唯一主题。背景分四层，越靠近用户的层越亮。

```
--bg-base      #0A0E15   页面底色
--bg-surface   #121824   卡片、面板
--bg-raised    #19202E   输入框、嵌套块、表头
--bg-overlay   #212A3A   悬停、选中
```

文字三级，均在对应背景上满足 WCAG AA：

```
--text-primary    #E7ECF5
--text-secondary  #9DA8BA
--text-tertiary   #7D899B
```

实测对比度（浏览器计算值）：一级 16.3、二级 7.4、三级 5.0（均相对 `--bg-surface`），
三级文字在最亮的 `--bg-raised` 上仍有 4.6，全部达标。

描边两级，用透明白以便叠在任意层上：

```
--border         rgba(255,255,255,.075)
--border-strong  rgba(255,255,255,.145)
```

品牌与交互色用蓝，避开红绿语义：

```
--brand          #3D7DF6   强调文字、链接、图表主色
--brand-hover    #5590FF
--brand-active   #2C68DC
--brand-subtle   rgba(61,125,246,.13)
--brand-border   rgba(61,125,246,.38)
--brand-solid    #2A63D6   实心按钮底色
```

实心主按钮单独用更深的 `--brand-solid`：白字压在 `--brand` 上只有 3.84:1，
压在 `--brand-solid` 上是 5.45:1。强调文字仍用较亮的 `--brand`，
它在 `--bg-base` 上是 5.03:1。

涨跌语义色遵循中文惯例，并各自配一个低饱和底色：

```
--up        #F04E4E   涨 / 盈利 / 正收益
--up-soft   rgba(240,78,78,.13)
--down      #22A875   跌 / 亏损 / 负收益
--down-soft rgba(34,168,117,.13)
--warn      #E0A33C
--warn-soft rgba(224,163,60,.12)
```

图表配色另设一组，避免与涨跌色冲突：策略权益用品牌蓝，基准用中性灰虚线，回撤用"跌"色填充（回撤恒为负，用跌色与全局语义一致），月度收益柱按正负取涨跌色。

考虑到平台同时覆盖美股，工作台提供一个涨跌配色切换（红涨绿跌 / 绿涨红跌），选择存 `localStorage`，默认中文惯例。

### 4.2 字体与数字

不加载 Web 字体，避免首屏阻塞和跨境字体 CDN 不稳定。

```
--font-sans: "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei",
             -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas,
             "Liberation Mono", monospace;
```

- 正文 14px，表格 13px，辅助说明 12px，标签 11px。
- 标题：`--fs-h1 28px`、`--fs-h2 22px`、`--fs-h3 17px`；落地页主标题单独放大到 `clamp(38px, 5vw, 60px)`。
- **所有数字使用 `font-variant-numeric: tabular-nums`**，保证纵向对齐。
- 代码、标的代码、回测 ID 用等宽字体；指标数值用无衬线 + 等宽数字，不用等宽字体（中文界面里全等宽会显得散）。
- 大额金额按中文习惯分节：≥1 亿用"亿"，≥1 万用"万"，保留两位小数。

### 4.3 间距、圆角、层次

间距使用 4px 基准刻度：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56`。

圆角整体收紧，传达工具感而非消费品感：

```
--radius-sm  4px   徽章、小按钮
--radius-md  8px   输入框、按钮、表格容器
--radius-lg  12px  卡片、面板
--radius-xl  16px  落地页大区块
```

阴影只用两级，且极克制。深色界面靠描边和背景层区分层次，不靠投影：

```
--shadow-sm  0 1px 2px rgba(0,0,0,.3)
--shadow-md  0 8px 24px rgba(0,0,0,.35)
```

### 4.4 组件规范

| 组件 | 规范 |
| --- | --- |
| 按钮 | 高 36px（`sm` 30px，`lg` 42px），圆角 8px，无渐变。主按钮实心品牌蓝；次按钮 `--bg-raised` + 描边；文本按钮无背景 |
| 输入 | 高 36px，背景 `--bg-raised`，聚焦时描边转品牌蓝 + 3px 低透明外发光 |
| 卡片 | 背景 `--bg-surface`，1px 描边，圆角 12px，内边距 20px；带标题时标题区 16px/20px 并以 1px 线分隔 |
| 指标卡 | 标签 12px 次级色 + 数值 24px 主色等宽数字 + 可选变化量；数值右侧留出趋势符号位 |
| 表格 | 13px，行高 38px，表头 `--bg-raised` 且 sticky，数字列右对齐，悬停整行高亮，无斑马纹 |
| 徽章 | 11px，圆角 4px，语义底色 + 同色文字 |
| 空状态 | 图标 + 一句说明 + 一个主操作按钮，垂直居中，最小高度 220px |
| 骨架屏 | `--bg-raised` 底 + 缓慢横向高光，用于指标卡、图表、表格首屏 |

### 4.5 图表规范

统一封装，所有图表共享同一套配置基线。

- 按需引入 ECharts 模块（`LineChart`、`BarChart`、`ScatterChart` + `Grid`、`Tooltip`、`Legend`、`MarkPoint`、`MarkLine`、`DataZoom`、`AxisPointer` + `CanvasRenderer`），替换当前的 `import * as echarts`。
- `axisPointer` 使用 `cross` 十字光标，`tooltip` 触发方式为 `axis`。
- 主图表提供 `dataZoom`（内置滚轮 + 底部滑块），支持区间下钻。
- 网格线只保留 y 轴横线，颜色 `rgba(255,255,255,.06)`，x 轴不画网格。
- 买卖点用三角标记而非文字圆点：买入为向上三角（涨色），卖出为向下三角（跌色）。
- 基准曲线固定为中性灰 1.5px 虚线，永远不抢主曲线视觉。
- 图表容器统一监听窗口尺寸变化并重绘（当前版本缺失，属于已有缺陷）。
- 每个结果图表下方带一行 12px 说明，解释这张图该怎么读。

## 五、信息架构

拆成两套外壳，解决"营销页塞进后台"的问题。

### 5.1 门户外壳（首页）

顶部横向导航，无侧边栏，内容最大宽度 1200px，用于对外说明产品。

```
顶栏：品牌 · 产品能力 · 研究流程 · 策略模板 · [进入研究工作台]
├─ 主张区      一句话定位 + 双 CTA + 右侧真实回测快照
├─ 能力条      4 项可验证的平台事实
├─ 研究流程    01→04 编号步骤
├─ 策略模板    6 张（当前只露出 3 张）
├─ 结果形态    说明一次回测会得到什么：指标 / 图表 / 明细 / 报告
├─ 快速开始    标的输入 + 常用标的 + 直接执行
└─ 页脚        风险提示常驻带 + 项目信息 + 备案位
```

### 5.2 工作台外壳（其余页面）

左侧固定侧边栏 216px（移动端抽屉），导航按任务阶段分组，而不是平铺七项：

```
研究    研究工作台 · 结果分析 · 回测记录
工具    参数优化 · 策略库
数据    数据管理
```

顶栏保留页面标题，右侧改为**全局状态区**：显示当前后端连通状态、数据来源、最近一次操作结果。状态从"一句话 pill"升级为有语义色和图标的状态条。

## 六、逐页面设计

### 6.1 研究工作台（lab）

左右两栏。左栏是分组表单，右栏是实时预览。

表单分四组，并补齐当前界面缺失的下单方式配置（`order_type`、`order_value`、`order_ratio` 后端早已支持，前端从未暴露）：

1. **研究对象** — 常用标的卡片、代码输入、资产类型、数据方式
2. **区间与成本** — 起止日期、初始资金、手续费、滑点
3. **策略与参数** — 策略选择 + 动态参数，每个参数带说明与默认值回填
4. **下单方式** — 全仓 / 固定金额 / 固定比例

右栏为标的快照（最新价、涨跌、区间高低、样本数）+ 走势图，数据未就绪时显示骨架屏。

底部为吸底操作条：运行回测（主）、预览数据（次）、重置参数（文本）。

### 6.2 结果分析（detail）

这一页改动最大，因为后端数据基本没被用上。自上而下五层：

1. **配置摘要条** — 标的、区间、策略、参数、初始资金、费率、滑点、数据来源，一行 chip 呈现，并提供 HTML / Markdown 报告导出
2. **指标区** — 全部 10 项指标，分三组呈现
   - 收益：总收益、年化收益
   - 风险：最大回撤、年化波动、夏普、卡玛
   - 交易：胜率、盈亏比、平均持仓天数、交易次数
3. **主图** — 价格走势 + 买卖点标记，带 `dataZoom`
4. **对照图** — 策略权益 vs 买入持有（同图）与回撤曲线（下方，共享 x 轴缩放）；右侧月度收益柱
5. **明细区** — 标签页切换
   - 交易明细：入场日、出场日、入场价、出场价、数量、盈亏、收益率、持仓天数
   - 订单流水：日期、方向、价格、数量、金额、手续费、滑点、状态

指标区与图表之间插入常驻风险提示："历史回测结果基于既有行情模拟，不代表未来表现，也不构成投资建议。"

### 6.3 回测记录（history）

从 5 列裸表格升级为可比较的研究台账：时间、标的、策略、区间、总收益、年化、最大回撤、夏普、交易次数、报告、操作。收益类列带涨跌色和符号，点击整行进入结果分析。无记录时显示空状态并引导到工作台。

### 6.4 参数优化（optimization）

左栏配置，右栏结果。

参数网格从裸 JSON 文本域改为**可视化网格编辑器**：每个参数一行，取值以 chip 形式增删，实时显示"当前组合数 = N"。保留"高级模式"切换回 JSON，兼容复杂输入。

右栏上方为收益–回撤散点图（最优点高亮），下方为完整排行榜表格：排名、参数、总收益、年化、最大回撤、夏普、胜率、交易数、查看。散点与表格行悬停联动。

### 6.5 策略库（strategies）

保留六个策略的完整说明（策略逻辑、信号含义、适用场景、参数说明、回测解读、产品展示要点、风险提示），但改为两栏紧凑布局：左侧策略列表可选中，右侧展示选中策略的完整说明，避免当前"六张长卡片纵向堆叠"造成的滚动疲劳。每个策略提供"用此策略新建回测"直达按钮。

### 6.6 数据管理（data）

缓存列表升级为标准表格（标的、类型、来源、行数、区间、操作），CSV 导入区改为带说明的拖放区，明确列出所需字段格式。空状态说明"当前使用在线数据，无需导入"。

## 七、状态与容错

| 状态 | 设计 |
| --- | --- |
| 首屏加载 | 指标卡、图表、表格分别显示骨架屏，不显示 `--` |
| 后端冷启动 | 首个请求超过 2.5 秒时，状态条提示"数据服务正在唤醒（免费实例冷启动），通常需要 30–60 秒"，并保持骨架屏 |
| 请求失败 | 就地显示错误原因（取 API `detail` 字段）+ 重试按钮，不再只在顶栏闪一行字 |
| 演示兜底 | 保留现有 `demoApi` 机制（静态托管或 API 不可用时接管），但界面必须显式标注"当前为演示数据" |
| 空数据 | 每个列表页有对应空状态与主操作 |

演示兜底的显式标注是本轮新增的要求。当前实现会在 API 不可用时静默切换到模拟数据，用户无法区分真假，这在金融产品里不可接受。

## 八、前端架构调整

现有实现把 7 个页面、模板、图表逻辑、演示数据全部写在单个 `frontend/src/main.js`（48KB）里。本轮内容量会显著增加，继续单文件不可维护，因此同步做结构拆分。

已验证 `@vitejs/plugin-vue` 6.0.7 在当前 Vite 8 / Vue 3.5 下可正常编译单文件组件并生成作用域样式，因此改用 SFC：

```
frontend/src/
  main.js                 应用入口
  api.js                  请求封装、错误解析、演示兜底
  format.js               百分比、金额、日期、代码格式化
  charts.js               ECharts 按需注册、主题、通用配置
  usePreferences.js       涨跌配色偏好
  styles/
    tokens.css            设计变量
    base.css              重置与基础排版
    components.css        按钮、表单、表格、卡片、徽章、骨架屏
  components/             通用组件
  pages/                  7 个页面组件
```

改用 SFC 后不再需要运行时模板编译器，并配合 ECharts 按需引入，预期把当前 1313KB 的产物显著压缩。

现有回归测试 `tests/test_product_homepage_copy.py` 与 `tests/test_deployment_config.py` 只读取 `frontend/src/main.js`。拆分后文案会分散到多个文件，测试改为**扫描 `frontend/src/` 全目录**，断言意图（禁止旧文案回归、保留产品文案、保留 API 兼容逻辑）完全不变，覆盖面反而更完整。

## 九、范围与边界

- 本轮只改前端与前端相关测试、文档。后端接口、数据结构、策略协议、回测逻辑、部署架构均不变。
- 不修改 Cloudflare WAF、托管质询或反机器人策略。
- 不引入账号体系、社区、付费或运营机制。
- 备案号位置在页脚预留，实际号码由项目所有者填写，本轮不编造。

## 十、验收标准

1. 全部后端测试通过，`npm run build` 通过。
2. 首页、工作台、结果分析、回测记录、参数优化、策略库、数据管理七个页面在 1440px、768px、390px 三档宽度下无横向溢出、无重叠。
3. 结果分析页展示全部 10 项指标、交易明细与订单流水。
4. 涨跌配色为红涨绿跌，且所有涨跌数字带 `+`/`-` 符号。
5. 回测结果区存在风险提示。
6. 首屏加载期间显示骨架屏而非 `--`。
7. 演示兜底数据在界面上有显式标注。
8. 键盘 Tab 可达所有交互元素且有可见聚焦环。
9. 线上正式域名 `https://quantlab.aihzcc.top` 可打开新版界面。

# 08 UI 升级调研与实施方案

## 目标

本轮升级面向量化研究使用者和团队决策者，目标不是增加新的量化能力，而是把首页从个人工具式引导改造成企业级产品入口，清晰呈现平台定位、标准研究流程、风险分析能力和研究资产沉淀方式。

成功标准：

- 访问者在首屏能明确识别 QuantLab 是量化策略研究、回测与报告管理平台。
- 首页采用企业产品语言，避免 AI 助手式对话、个人化劝导和消费级“免费体验”话术。
- 首页以研究任务、策略模板、风险分析和报告归档说明平台能力，不虚构用户数、收益率或客户背书。
- 桌面端和移动端均能创建研究任务、加载数据预览并执行标准回测。
- 不改变现有回测 API、数据结构、策略协议与部署架构。

## 同类产品观察

### QuantConnect

- 公开页面把 Research、Backtest、Optimize、Live Trading 串成完整流程，用户先理解工作流，再进入具体工具。
- 页面用平台规模、社区和基础设施能力建立可信度。
- 对 QuantLab 的启发：保留“从想法到报告”的完整闭环，但现阶段只展示可验证的产品能力，不使用未经证实的用户规模数字。

来源：<https://www.quantconnect.com/>

### Composer

- 核心入口强调创建策略、回测和自动化，首屏直接给用户明确动作。
- 可视化编辑和无需编码降低首次体验门槛，策略卡片承担示例与教育作用。
- 对 QuantLab 的启发：首页同时提供“免费开始研究”和“一键生成示例结果”，策略库在首页露出，而不是要求用户先理解全部参数。

来源：<https://www.composer.trade/>

### TradingView Strategy Tester

- 结果区域按 Overview、Performance Summary、List of Trades、Properties 等层次组织，先给关键指标，再允许深入交易明细。
- 支持基准比较和图表联动，结果不是单一收益数字，而是完整证据链。
- 对 QuantLab 的启发：首页需要预告“收益、回撤、买卖点、月度表现、报告”等结果形态，强化可解释性，而不是只强调运行回测。

来源：<https://www.tradingview.com/support/solutions/43000764138-an-overview-of-the-strategy-tester/>

### Koyfin

- 以可定制看板和高密度可视化作为产品吸引力，强调在一个工作区完成研究。
- 对 QuantLab 的启发：保留深色专业工作台，但首屏需增加更清楚的视觉层级和产品化叙事，避免看起来像只面向内部人员的后台系统。

来源：<https://www.koyfin.com/>

## 本轮设计决策

### 1. 首屏采用企业平台定位

主标题明确为“统一策略研究、回测验证与报告管理”，面向投研、产品与技术团队说明平台职责。右侧保留真实研究分析视图，形成“平台定位 + 产品能力证明”的首屏结构。

### 2. 首页入口改为标准研究任务

保留首页快速研究表单，但统一使用“创建研究任务、加载数据预览、执行标准回测”等业务术语。常用研究对象继续支持一键填充，降低操作成本但不采用助手式引导。

### 3. 用能力矩阵替代消费级卖点

首页不展示无法验证的注册用户数、累计回测数或收益承诺，也不强调“无需注册”等消费级转化话术；改为展示策略模板、市场范围、分析维度和报告交付格式。

### 4. 强调研究治理与资产沉淀

首页使用“定义任务 → 执行回测 → 评估风险 → 归档成果”的标准流程，并露出策略模板、参数实验和报告资产，支持团队评审与复盘。

### 5. 提升品牌识别与分享表现

增加品牌图标、页面描述、Open Graph 元数据、键盘焦点样式、移动端布局和减少动态效果偏好支持。

## 范围与边界

本轮只修改前端体验、公开页面元数据、相关测试和文档；后端接口与量化逻辑保持不变。部署时前端发布到 Cloudflare Pages，后端继续使用 Render 的现有 FastAPI 服务并执行健康检查。Cloudflare 当前可能对自动化访问返回托管质询；该设置属于安全/反机器人路径，本轮不擅自修改。

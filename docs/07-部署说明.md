# 07 部署说明

## 当前生产部署结构

| 模块 | 平台 | 地址 | 说明 |
| --- | --- | --- | --- |
| 前端 Web | Cloudflare Pages | `https://quantlab-cn2.pages.dev` | 当前稳定、可直接访问的公开入口 |
| 后端 API | Render Web Service | `https://quantlab-api-t4cv.onrender.com` | FastAPI 后端稳定入口 |
| API 健康检查 | Render Web Service | `https://quantlab-api-t4cv.onrender.com/api/strategies` | 用于确认后端可用 |
| 代码源 | GitHub | `https://github.com/hhzz-svg/QuantLab` | 前后端和部署配置统一来源 |

生产前端使用 `VITE_API_BASE_URL=https://quantlab-api-t4cv.onrender.com` 直接调用 Render 后端。这样可以绕开自定义域名当前的 Cloudflare Managed Challenge，保证公开入口和前端 API 请求可直接使用。前端仍保留静态演示兜底逻辑，应对 API 短时不可用。

## Render 后端配置

Render Web Service 使用 GitHub 仓库 `hhzz-svg/QuantLab`：

| 配置项 | 值 |
| --- | --- |
| Name | `quantlab-api` |
| Branch | `main` |
| Runtime | `Python` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn backend.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/strategies` |

环境变量：

| Key | Value |
| --- | --- |
| `PYTHON_VERSION` | `3.12.10` |
| `DATABASE_URL` | `sqlite:////opt/render/project/src/data/quantlab.db` |

当前 SQLite 适合轻量演示和项目评审。如果后续进入多人协作或长期生产使用，应另行评估托管数据库；数据库结构和迁移不属于本轮 UI 升级范围。

## Cloudflare Pages 前端配置

Cloudflare Pages 项目名为 `quantlab`，生产分支为 `main`。生产构建使用：

```text
VITE_API_BASE_URL=https://quantlab-api-t4cv.onrender.com
```

部署完成后访问：

```text
https://quantlab-cn2.pages.dev
```

构建产物应调用 Render 稳定入口，不应依赖需要交互式质询的 API 域名。

## 自定义域名边界

以下自定义域名继续保留，但当前脚本和无状态浏览器访问会触发 Cloudflare Managed Challenge：

```text
https://quantlab.aihzcc.top
https://api.quantlab.aihzcc.top
```

在 WAF 或反机器人策略获得明确批准并完成验证前，不把这两个地址作为主要公开入口，也不让生产前端依赖自定义 API 域名。本轮不修改 Cloudflare WAF、托管质询或反机器人策略。

## 本地验证命令

```powershell
cd D:\QuantLab\quant-backtest-system
python -m pytest -q -p no:cacheprovider
python -m compileall backend -q
$env:VITE_API_BASE_URL='https://quantlab-api-t4cv.onrender.com'
npm run build
```

## 线上验证命令

```powershell
Invoke-WebRequest https://quantlab-api-t4cv.onrender.com/api/strategies -UseBasicParsing
Invoke-WebRequest https://quantlab-cn2.pages.dev -UseBasicParsing
```

验收标准：

- API 健康检查返回 HTTP 200。
- 前端首页返回 HTTP 200，并包含新版产品标题。
- 前端生产构建使用 `https://quantlab-api-t4cv.onrender.com`。
- GitHub `main`、Render live deployment 和 Cloudflare Pages production deployment 对应同一提交。

## 回滚方式

- 后端回滚：在 Render 中回滚到上一版 live deployment。
- 前端回滚：在 Cloudflare Pages 中回滚到上一版 production deployment。
- 入口回滚：README 与部署文档恢复到上一提交，并重新部署对应前端构建。
- 数据回滚：当前 SQLite 适合演示使用；如使用托管数据库，应以数据库备份和迁移记录作为正式回滚点。

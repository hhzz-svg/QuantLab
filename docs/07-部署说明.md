# 07 部署说明

## 当前生产部署结构

| 模块 | 平台 | 地址 | 说明 |
| --- | --- | --- | --- |
| 前端 Web | Cloudflare Pages | `https://quantlab.aihzcc.top` | 面向用户的线上访问入口 |
| 后端 API | Render Web Service | `https://api.quantlab.aihzcc.top` | FastAPI 后端服务 |
| API 健康检查 | Render + Cloudflare DNS | `https://api.quantlab.aihzcc.top/api/strategies` | 用于确认后端可用 |
| 代码源 | GitHub | `https://github.com/hhzz-svg/QuantLab` | 前后端和部署配置统一来源 |

当前前端通过生产环境变量 `VITE_API_BASE_URL=https://api.quantlab.aihzcc.top` 调用 Render 后端。前端仍保留静态演示兜底逻辑，避免 API 短时不可用时公开入口直接失效。

## Render 后端配置

在 Render Dashboard 新建 Web Service，选择 GitHub 仓库 `hhzz-svg/QuantLab`。

| 配置项 | 值 |
| --- | --- |
| Name | `quantlab-api` |
| Branch | `main` |
| Runtime | `Python` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn backend.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/strategies` |

环境变量：

| Key | Value |
| --- | --- |
| `PYTHON_VERSION` | `3.12.10` |
| `DATABASE_URL` | `sqlite:////opt/render/project/src/data/quantlab.db` |

当前 SQLite 适合轻量演示和项目评审。如果后续要进入生产级协作，建议把 `DATABASE_URL` 切换为 Render Postgres 或其他托管数据库，并补充对应数据库驱动依赖。

## 后端自定义域名

Render 服务创建完成后，在 Render 的 Custom Domains 中添加：

```text
api.quantlab.aihzcc.top
```

然后在 Cloudflare DNS 中添加 Render 提示的 CNAME 记录。记录生效后，用下面地址验证后端：

```text
https://api.quantlab.aihzcc.top/api/strategies
```

预期结果：HTTP 200，并返回策略列表 JSON。

## Cloudflare Pages 前端配置

在 Cloudflare Pages 项目 `quantlab` 中设置生产环境变量：

```text
VITE_API_BASE_URL=https://api.quantlab.aihzcc.top
```

保存后重新部署前端。部署完成后访问：

```text
https://quantlab.aihzcc.top
```

确认线上前端加载的构建产物中不再指向 Render 临时域名，而是统一调用正式 API 域名。

## 本地验证命令

```powershell
cd D:\QuantLab\quant-backtest-system
python -m pytest -q
python -m compileall backend -q
npm run build
```

## 线上验证命令

```powershell
Invoke-WebRequest https://api.quantlab.aihzcc.top/api/strategies -UseBasicParsing
Invoke-WebRequest https://quantlab.aihzcc.top -UseBasicParsing
```

验收标准：

- API 健康检查返回 HTTP 200。
- 前端首页返回 HTTP 200。
- 前端生产环境 API 地址为 `https://api.quantlab.aihzcc.top`。
- GitHub `main` 分支、Render 服务和 Cloudflare Pages 构建源保持一致。

## 回滚方式

- 后端回滚：在 Render 中回滚到上一版部署，或临时暂停 `quantlab-api` 服务。
- 前端回滚：在 Cloudflare Pages 中回滚到上一版构建。
- 域名回滚：在 Cloudflare DNS 中删除或调整 `api.quantlab.aihzcc.top` 的 CNAME 记录。
- 数据回滚：当前 SQLite 适合演示使用；如使用托管数据库，应以数据库备份和迁移记录作为正式回滚点。

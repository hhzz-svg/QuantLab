# 07 部署说明

## 当前生产部署结构

| 模块 | 平台 | 地址 | 说明 |
| --- | --- | --- | --- |
| 前端 Web（正式） | Cloudflare Pages | `https://quantlab.aihzcc.top` | QuantLab 对外正式访问入口 |
| 前端 Web（备用） | Cloudflare Pages | `https://quantlab-cn2.pages.dev` | 自定义域名排障时使用的技术备用入口 |
| 后端 API | Render Web Service | `https://quantlab-api-t4cv.onrender.com` | FastAPI 后端稳定入口 |
| API 健康检查 | Render Web Service | `https://quantlab-api-t4cv.onrender.com/api/strategies` | 用于确认后端可用 |
| 代码源 | GitHub | `https://github.com/hhzz-svg/QuantLab` | 前后端和部署配置统一来源 |

生产前端使用 `VITE_API_BASE_URL=https://quantlab-api-t4cv.onrender.com` 直接调用 Render 后端，避免前端 API 请求依赖当前会触发 Cloudflare Managed Challenge 的自定义 API 域名。前端仍保留静态演示兜底逻辑，应对 API 短时不可用。

## Render 后端配置

Render Web Service 使用 GitHub 仓库 `hhzz-svg/QuantLab`：

| 配置项 | 值 |
| --- | --- |
| Name | `quantlab-api` |
| Branch | `main` |
| Runtime | `Python` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn backend.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/strategies` |

环境变量：

| Key | Value |
| --- | --- |
| `PYTHON_VERSION` | `3.12.10` |
| `DATABASE_URL` | `sqlite:////opt/render/project/src/data/quantlab.db` |

当前 SQLite 适合轻量演示和项目评审。如果后续进入多人协作或长期生产使用，应另行评估托管数据库；数据库结构和迁移不属于本轮 UI 升级范围。

## Cloudflare Pages 前端配置

Cloudflare Pages 项目名为 `quantlab`，生产分支为 `main`。生产构建使用：

```text
VITE_API_BASE_URL=https://quantlab-api-t4cv.onrender.com
```

部署完成后通过正式域名访问：

```text
https://quantlab.aihzcc.top
```

Cloudflare Pages 技术备用入口：

```text
https://quantlab-cn2.pages.dev
```

构建产物应调用 Render 稳定入口，不应依赖需要交互式质询的 API 域名。

## 自定义域名边界

`https://quantlab.aihzcc.top` 是 QuantLab 正式 Web 入口，已经绑定 Cloudflare Pages。当前脚本和无状态浏览器访问该域名可能触发 Cloudflare Managed Challenge；这不改变正式域名归属，但自动化健康检查应改用 Pages 技术备用入口。

自定义 API 域名 `https://api.quantlab.aihzcc.top` 当前同样可能触发质询，因此生产前端继续直接调用 `https://quantlab-api-t4cv.onrender.com`。本轮不修改 Cloudflare WAF、托管质询或反机器人策略。

## 行情数据源容错

Render 后端在 `data_source=auto` 时按标的类型选择行情链：

- 美股：先使用 yfinance；若返回空数据或请求异常，再请求 Yahoo Chart 接口。
- A 股和 ETF：先使用 AKShare 的 Eastmoney 行情；若连接被远端关闭或返回空数据，再使用 AKShare 的新浪行情。
- 两条在线链均不可用时，API 明确提示稍后重试或上传 CSV，不使用示例数据代替真实标的。

`requests` 是 Yahoo Chart 备用请求的显式运行依赖，由 `requirements.txt` 随 Render 构建安装。

## 前端构建说明

前端为 Vue 3 单文件组件，构建依赖 `@vitejs/plugin-vue`（已在 `package.json` 中声明）。
图表按需引入 ECharts 模块，不再整包导入。构建入口与产物路径不变，Cloudflare Pages 配置无需调整。

## 线上验证命令

```powershell
Invoke-WebRequest https://quantlab-api-t4cv.onrender.com/api/strategies -UseBasicParsing
Invoke-WebRequest https://quantlab-cn2.pages.dev -UseBasicParsing
# 正式域名请使用普通浏览器验收，自动化请求可能触发 Cloudflare Managed Challenge
Start-Process https://quantlab.aihzcc.top
```

验收标准：

- API 健康检查返回 HTTP 200。
- Cloudflare Pages 技术备用入口返回 HTTP 200，并包含新版产品标题。
- 普通浏览器可通过正式域名 `https://quantlab.aihzcc.top` 打开新版首页；如出现 Managed Challenge，须单独审批 WAF 或反机器人策略调整。
- 前端生产构建使用 `https://quantlab-api-t4cv.onrender.com`。
- GitHub `main`、Render live deployment 和 Cloudflare Pages production deployment 对应同一提交。

## 回滚方式

- 后端回滚：在 Render 中回滚到上一版 live deployment。
- 前端回滚：在 Cloudflare Pages 中回滚到上一版 production deployment。
- 入口回滚：README 与部署文档恢复到上一提交，并重新部署对应前端构建。
- 数据回滚：当前 SQLite 适合演示使用；如使用托管数据库，应以数据库备份和迁移记录作为正式回滚点。
